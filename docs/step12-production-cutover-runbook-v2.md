## Non-negotiable writer invariant

Canonical scoring authority and mutation admission are separate facts. The only
supported forward states are:

```text
GOOGLE canonical / legacy admission OPEN
  -> GOOGLE canonical / legacy admission CLOSING
  -> GOOGLE canonical / legacy admission CLOSED
  -> GOOGLE canonical / Supabase epoch PREPARED / both ingresses paused
  -> SUPABASE canonical / legacy admission CLOSED
```

`GOOGLE admission OPEN + SUPABASE ingress OPEN` is forbidden. A scoring pause
is acceptable; ambiguous or dual authority is not.

## Forward phase sequence

For every phase, recapture state, verify the prior receipt, record the new
activation/admission revision and generations, and classify rollback before
advancing. Preserve the staged environment/certification claims and rebind the
current execution-bundle fingerprint before generating the next payload.

1. `DORMANT -> STAGED`
   - Stage the exact frozen release.
   - No persistent-fence IDs exist yet and none are supplied to stage.
   - Google scoring and Passport identity remain canonical.
   - Legacy admission remains `OPEN`.

2. `STAGED -> STATIC_BACKEND`
   - Deploy the barrier-aware candidate with legacy authority preserved.
   - Verify exact Production resources and the complete origin/credential
     matrix.
   - The candidate must fail closed when admission cannot be verified.

3. `STATIC_BACKEND -> READ_CUTOVER -> IDENTITY -> CURRENT_READS`
   - Follow the separately certified read and identity transitions.
   - Google remains canonical scoring authority.
   - Legacy admission may remain `OPEN`.
   - Arm the barrier-aware legacy admission protocol for the exact candidate,
     then execute the quiesce/install sequence above and record the external
     fence evidence from its quiesce, fence, and verification IDs. Remove the
     exact temporary WAF rule and pass the immediate post-removal edge/read
     health checks before recording or closing; do not leave the project-wide
     deny window open while performing unrelated phases.

4. Close legacy admission atomically
   - Call `close_production_scoring_admission` with the current activation,
     authority, admission revisions/generations, provider-fence evidence ID,
     exact quiesce/fence/verification IDs, exact resource tuple, deployment
     ID/SHA, and durable request identity.
   - One transaction changes admission `OPEN -> CLOSING`, pauses execution,
     records a lease high-watermark, and prevents new v2 admissions.
   - The close boundary serializes with an admitted canonical transaction. If
     admission won first, close waits for that canonical database transaction;
     durable outbox/archive work created by the transaction remains visible and
     still has to drain. A returned close receipt does not imply that durable

   - Call `finalize_production_scoring_admission` with the stable final Google

## Machine-checkable safety predicates

`FINAL_GOOGLE_AUTHORITY_SNAPSHOT_SAFE` requires:

- authority `GOOGLE` and admission `CLOSED`;
- exact Production project/workbook/tournament;
- active, potential, ambiguous, partial, and legacy-unclassified writers `0`;
- current provider-fence evidence;
- no conflicting prepared epoch;
- zero unresolved canonical queue work; and
- stable Google readback bound to the current revisions/generations.

`SUPABASE_AUTHORITY_PREPARE_SAFE` additionally requires an immutable final
Google fingerprint and exact shadow parity.

`SUPABASE_AUTHORITY_COMMIT_SAFE` additionally requires the valid prepared
epoch, unchanged closure/provider/fingerprints, paused Supabase ingress, exact
precommit deployment configuration, and first-write markers still false.

`LEGACY_GOOGLE_REOPEN_SAFE` is false while Supabase is canonical, a prepared
epoch exists, any Supabase-window write is unreconciled, rollback is incomplete,
or a newer operator revision has advanced the transition.

## Failure and idempotency rules

- Duplicate close/finalize/reopen requests use durable request identities and
  return the authoritative existing result or a stale-revision rejection.
- A lost close response never triggers a reopen. Inspect state first.
- A failed/ambiguous Google transport blocks closure until explicit readback
  resolves it.
- Aborting a prepared epoch leaves Google canonical with admission `CLOSED`.
  Reopen is a separate audited operation.
- Do not automatically reopen after a provider, fingerprint, parity, deployment,
  or Supabase failure.

## Rollback matrix

| State | Supabase authority | Supabase write observed | Legacy admission | Safe rollback |
|---|---:|---:|---|---|
| Before close | No | No | OPEN | Normal legacy operation |
| CLOSING | No | No | CLOSING | Resolve/drain, abort, then explicit safe reopen |
| CLOSED pre-prepare | No | No | CLOSED | Explicit safe reopen |
| Prepared | No | No | CLOSED | Abort epoch, then explicit safe reopen |
| Committed/no write | Yes | No | CLOSED | Pause Supabase, roll back authority, then reopen |
| Committed/post-write | Yes | Yes | CLOSED | Pause, enumerate/reconcile, roll back authority, then reopen |

Never reopen Google before authority is safely Google again. Unexpected Google
divergence after commit is a reconciliation incident even when no Supabase write
has been observed.

### Supported post-commit rollback sequence

Rollback uses a second admission closure; it does not reuse or reopen the
consumed legacy closure and it does not flip source configuration first.

1. Call `close_production_scoring_admission` with
   `expected_authority=SUPABASE`. In one transaction the Supabase ingress gate
   becomes `PAUSED` and a `SUPABASE_INGRESS` closure is created. Legacy Google
   admission remains `CLOSED`.
2. Call `drain_production_scoring_admission` for that exact closure. A racing
   Supabase mutation is serialized by the same advisory lock and remains in the
   drain set until its transaction is definitively resolved.
3. Enumerate the complete Supabase authority-window write set. For post-write
   rollback, reconcile it into the Google rollback target and require
   unresolved, lost, and duplicate counts all equal `0`.
4. Call `finalize_production_scoring_admission` for the
   `SUPABASE_INGRESS` closure with the stable reconciled fingerprints and exact
   revisions/checkpoints. The execution gate remains `PAUSED`.
5. Call `prepare_production_authority_epoch(ROLLBACK)` using that closed
   Supabase-ingress closure, then `commit_production_authority_epoch` for the
   prepared rollback epoch.
6. Only after the rollback commit proves Google canonical and Supabase ingress
   unavailable may `reopen_production_scoring_admission` create a fresh legacy
   admission generation. Restore provider capability only as part of that same
   certified rollback sequence.

A post-commit/no-write rollback follows the same ordering but has an empty
Supabase authority-window mutation set. There is no supported direct transition
from `SUPABASE canonical` to `GOOGLE admission OPEN`.

## Cutover-pause client behavior

During `CLOSING`, `CLOSED`, and prepared precommit states, participant scoring
must fail with a recoverable response equivalent to:

> Scoring is temporarily paused while tournament state is updated. Refresh shortly.

The client must not queue an unbounded retry, silently select another authority,
