## Critical findings added by this expansion

1. **Round-state fingerprints are time-volatile.** The round manifest includes the count of leases satisfying `expires_at > clock_timestamp()`. The same rows can therefore yield a different fingerprint after wall-clock passage. This is source-proven and should be separated from the semantic state digest.
2. **The Production Odds publication request fingerprint does not bind two accepted predecessor arguments.** `expectedPublicationRevision` and `expectedSnapshotId` are validated and sent to the RPC but omitted from the hash input. Database compare-and-swap may still protect the write; the fingerprint’s advertised meaning is narrower than the function signature.
3. **Future scoring preparation does not directly hash all snapshot scoring values.** Round handicap allowance and tee rating/slope/par are written to the snapshot but absent from both the preparation manifest and the final snapshot hash except through revision dependencies.
4. **Normal pairing edits lack a dedicated state fingerprint.** The setup RPC hashes the whole request, while the one-time R3 recovery builds a real canonical pairing digest. Request idempotency and current pairing authority should be separate artifacts.

## Reachable functions and chains not fully traced

The following scope remains genuinely unproven:

- installed database definitions and migration application order in the actual 2026 environment;
- runtime reachability of every source definition and every annual dispatch branch;
- dynamic calls to `assert_future_scoring_runtime_capability_v1` and `bind_future_participant_identity_runtime_v1` in `202608300066...sql:2921-2938`;
- the body and all producers of `handicap_v1_roster_fingerprint(...)`, called at `202608300066...sql:3400-3402`;
- the legacy `production_maintenance_stage_provenance_v1` semantic payload/database fingerprint bodies reached by migration 050;
- all database checks behind the application-side Odds publish and withdrawal RPCs;
- caller provenance for base request fingerprints accepted by the Production Calcutta and Net Skins server helpers;
- proof that every field included in broad input snapshots is consumed, and that every consumed field omitted from a manifest is protected by an enforced revision dependency;
- hashes created by dynamic SQL, generated artifacts, extensions, or repository paths outside the bounded files listed here;
- collision resistance, canonicalization parity across Node/PostgreSQL, performance bounds, and physical-device behavior. No execution was performed.

These limits require the package to retain **PARTIAL** coverage for Part XXI. They do not negate the source-proven field inventories or omissions above.
