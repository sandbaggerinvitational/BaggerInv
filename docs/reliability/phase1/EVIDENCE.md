## Machine evidence and freshness

`tools/reliability/certify-phase1.mjs --sql` emits [LOCAL-EVIDENCE.json](LOCAL-EVIDENCE.json). It records suite, declared layer, exact test path, start/end, exit result, pass/fail/skip counts, output digest, environment, Git HEAD/dirty state, source-file SHA-256 manifest and artifact digests. The source inventory includes the installed migrations, incremental SQL repairs and candidate SQL, not merely application JavaScript.

A dirty-tree HEAD is not advertised as the full candidate identity: the manifest identifies the actual tested source. A later commit may contain these identical source bytes plus evidence documents. Source or fixture changes invalidate affected proof; documentation-only changes do not imply an untested runtime. Benchmark timestamps/methods are independent of the collector run. The evidence is not automatically refreshed by writing a PASS sentence.

Native candidate gates are separate from passing historical reproductions. A missing checkout or simulator cannot qualify as repaired behavior. The future tournament orchestrator must consume both the catalog's required corrected gates and physical/lifecycle evidence.

## What is unavailable

No Production resource, restart, Disk I/O, pool, backup, restore or current operational-state proof was collected. See [capacity gaps](CAPACITY-EVIDENCE-GAPS.md). Internal PostgreSQL idempotency/stroke/net/audit subphase durations are not exposed by the installed API; query plans and RPC timings do not fabricate those fields. Full R1–R3 chronology, physical scoring, supported mixed native versions, soak/load, provider failure and durable telemetry delivery remain separate gates.
