# Private control and scheduler protocol

## Durable state

Five private, RLS-enabled tables: `worker_supervisor_v1`, `worker_supervisor_invocations_v1`, `worker_supervisor_receipts_v1`, `worker_supervisor_faults_v1`, `worker_supervisor_installation_v1`. No client policies or role memberships are added. All table access and private function execution are revoked from PUBLIC/anon/authenticated/service_role. The sole new public service-role wrapper is a closed control protocol requiring the exact registered binding and a valid reservation/signature or private run token. It cannot START/STOP/configure/arm faults or choose a worker operation.

Control state contains epoch/revision, immutable binding/context/digest, fixed engine scope, expiry, aggregate budget, slot ceiling, Vault UUID references, last invocation/tick, next due time, durable global/invocation failure counts and halt evidence. Invocation state contains single-use nonce/sequence, recorded ticket, expiry, hashed run token, step sequence, durable tick/finish evidence and claim/reconciliation evidence. STATUS returns sanitized identities/counts/classes; it never returns signing keys, bypass keys, signatures, run/claim tokens, participant records or financial payloads.

Owner controls are private SQL operations under the existing managed owner/provisioning connection; no browser API is provided. START and STOP have UUID request receipts, replay/idempotency and conflicting-request rejection. START compares current initialized resource, release, authority epoch and activation/admission/pointer revisions, safe outstanding state and explicit limits. STOP invalidates future reservations and steps, leaving in-flight outcomes truthful. RESUME requires corrected cause/reconciliation evidence and clean claims/outcomes; it creates a new epoch without resetting job attempts. A stale stored deployment target latches HALTED instead of repeatedly dispatching the old target.

## Signature and admission

HMAC-SHA256 authenticates UTF-8 `POST`, the fixed `/api/internal/derived-worker/run` path, exact immutable origin, and SHA256 of the exact body, separated by newlines. SQL signs `jsonb::text`; pg_net serializes that same text. No query-string credentials, redirects or client resource parameters. Body limit 2048 bytes, exactly eight fields: contract, invocation_id, nonce, epoch, revision, binding_digest, issued_at, expires_at. TTL is 30 seconds; the receiver checks timestamp, shape, origin and constant-time HMAC, then SQL atomically consumes the recorded reservation once. BEGIN revalidates current enabled supervisor/binding/runtime prerequisites; STEP enforces sequence and the 45-second cutoff. Host/forwarded headers never provide authority.

Single-use run tokens are generated only after BEGIN and stored hashed. Accounting operations await durable acknowledgements. Optional telemetry never proves success. Missing accounting/network acknowledgements leave uncertainty for canonical reconciliation. Reconciliation waits 120 seconds and records actual work cycles, statuses, attempts and source identities; it never equates missing HTTP response with rollback.

## Provider secrets and ACL prerequisites

Later provisioning generates an independent Certification signing secret, stores it in Supabase Vault and the exact Certification Preview branch's server-only `CERTIFICATION_WORKER_SIGNING_KEY`, and records only Vault UUID references through owner configure. A scoped Vercel protection bypass, if required, is separate and provides no route authority. Existing database/SMTP/management/session secrets are not supervisor keys.

Before scheduling or enqueuing headers, the provider ACL guard denies any anon/authenticated/service_role table privilege in `net` or `vault`. Installation must review actual extension/version/owners/permissions and restrict PUBLIC grants on queues, responses, decrypted view and helpers. The code deliberately fails closed rather than inheriting unsafe extension defaults. No provider configuration is changed by this local package.

Forward installation requires the exact registered Certification physical resource, disabled admission and paused ingress. Replay verifies its private installation image (function bodies/security/search_paths/owners/ACLs, relation shape/constraints/RLS) before replacing definitions. Unexpected or unreceipted add-on state is denied. Existing baseline installation receipt, registration, canonical function definitions, ACLs, owners, RLS and schema artifacts remain unchanged; the add-on has its own receipt. Fresh installation order is the certified baseline, registration/initialization and fixture, prior approved forward corrections, then this OFF add-on. Historical migrations/bootstrap artifacts are not regenerated.
