# Worker and recovery operations boundaries

The supported worker is a process-lifetime service loop, not a request callback. Its local child-process proof shows autonomous pickup while alive, restart recovery and durable ownership. It does not install a hosted scheduler, daemon, cron or provider resource. No claim of hosted unattended availability is made.

Ordinary automated scope: bounded score-intent materialization; existing private Calcutta, competition and intelligence calculations; transient retry; expired-lease recovery; exact compatible supersession. It must never alter gross scores, handicaps, pairings, auction ownership, entry membership or public publication to clear a blocker. NetSkins calculation/configuration and all public/financial approval remain explicit owner actions.

Terminal recovery requires a current authorized Director, exact work identity, expected cycle/attempt, request UUID and reason. The same request is idempotent; different payload under the same request conflicts. Requeue preserves prior attempts, validates current financial source/generation and does not override Final recap's owner-published Final Odds prerequisite. If underlying cause remains, the new bounded cycle may fail visibly again. There is no universal ignore-guards switch.

Recovery is a read, not a scoring lease: a current verified participant may inspect only their immutable originating mutation receipt. COMMITTED instructs no resubmission. UNKNOWN instructs status/reconciliation; absence is not permanent noncommit. Never create a new mutation merely because response delivery failed. Legacy unbound receipts require a future explicitly authorized operator workflow, not inferred ownership.

## Retention proposal — not implemented deletion

Keep pending, running and dead-letter work in operational storage until explicitly reconciled; never age it out because it is inconvenient. Preserve exact mutation ownership and accepted acknowledgement throughout supported retry/recovery/incident windows. Archive completed delivery attempts with their immutable work/cycle/source/release links only after audit/legal/privacy policy approval and a tested exact-lookup archive contract. No numeric TTL is guessed and no cleanup job is added here.

Indexes support current due/terminal work and exact attempt lookups. Periodic deep historical diagnosis belongs in maintenance snapshots, not live tournament scoring. Later hosted operation needs distributed admission, alerts, supervised restart, bounded worker connections and tested retention/restore. Those are separate readiness gates.
